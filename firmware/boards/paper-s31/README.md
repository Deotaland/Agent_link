# 墨之坊 paper V2 / ESP32-S31

## WiFi 平台固件

`paper-s31-wifi` 使用 Agent_link 的 WiFi 通道，平台为 `https://bot.zhaojun.work`，
产品 ID **16**（`paper-s31`），`chip_type` 为 `esp32-s31`。
它使用正常的 SDK 入口、设备认证、热点配网、激活绑定、MQTT 控制和实时语音。

在已激活的 ESP-IDF 6.1 环境中，从 `firmware` 目录编译：

```powershell
python tools/build_firmware.py paper-s31-wifi --jobs 2
```

首次使用：

1. 设备没有已保存的网络时，手机连接 `PaperS31-XXXX` 热点，打开 `192.168.4.1` 配网。
2. 屏幕显示六位激活码后，在平台的设备管理中用激活码添加设备，并绑定 Agent。
3. 短按 BOOT：如果没有已选会话，打开会话选择；否则开始通话。通话中短按 BOOT 结束。
4. 空闲时长按 BOOT 超过 1 秒并松开，打开会话选择。短按切换，长按选中。
   会话列表包含“新建会话”和“返回”，切换到本页末尾后继续短按会读取下一页，最后一页后回到第一页。
5. 等待会话候选项刷新到屏幕，再进行下一次选择；屏幕尚未刷新时忽略菜单按键，避免误选。

会话选择按绑定的 Agent 保存在 NVS；平台换绑后清除旧会话选择并结束旧通话。
麦克风只在语音连接就绪后开始连续上传，喇叭播音及其尾音期间上传静音以减少回声，
没有声学回声消除或语音打断。平台下发文本、震动、LED 和录音请求通过正常 SDK 回调处理。

S31 没有当前版本的 Opus 预编译库，所以此方案明确协商 **PCM16**：
上行 16 kHz、下行 24 kHz，SDK 转成 16 kHz 后播放。麦克风双声道下混为单声道，
喇叭单声道复制到左右声道。平台需接受 PCM16 配置；若返回 Opus，固件会拒绝不支持的格式。

屏幕仅支持 ASCII，中文暂以 `?` 代替。六色屏每次全刷约 15 秒，仍会闪动，
当前面板没有可用的局刷或无闪烁模式。网络和音频运行在独立任务。

刷新调度先等待页面稳定 3 秒，再比较最终显示的文字行；相同画面不触发全刷。
普通自动更新在上次刷新完成后至少等待 180 秒。激活码、稳定错误、上线、
手动菜单操作和稳定回复可提前更新，但距离上次刷新完成仍至少等待 10 秒。
配网进度和激活倒计时不逐秒重刷；电量、充电状态只在其他内容需要刷新时一起更新。
回复收到音频结束信号或文字连续 5 秒不变后才送入屏幕调度。
刷新失败后至少等待 60 秒再尝试，避免持续重复全刷。

离线或连接中，子板 LED 每秒切换；上线时短震动，按 BOOT 也有短震动反馈。
在线时平台仍可控制 LED。按键反馈不需要等待墨水屏，但菜单选择仍需等待当前候选项显示完成。
日志中的 `Display refresh starting/finished` 会标出实际全刷次数和每次耗时。

WiFi 方案启用 ESP-IDF 的交叉签名证书链校验，继续使用完整可信证书包和域名校验，
适配平台当前的证书链。GPIO19 只由板级初始化配置，音频负责功放开关，codec 不重复配置该引脚。
如果平台无绑定 Agent、Agent 不支持语音或创建会话失败，屏幕会提示，不虚报通话成功。

固件构建和主机 API 测试不代替实机验收。仍需验证配网、产品 16 激活、MQTT、
真实平台 PCM16 通话及屏幕显示。尚未执行烧录或操作真实平台设备。

## 离线板级演示

`paper-s31-offline` 是离线板级演示方案，不启动 WiFi、BLE 或平台连接。
驱动移植自用户提供的 `E:\Deotaland\blink`，生产代码保存在此目录，应用入口在
`firmware/apps/paper-s31/paper_s31.cc`。参考项目中的图片和测试框架未带入。

## 屏幕与接线

本方案固定使用 **Waveshare 3.6inch e-Paper (E)，400×600，六色**。
接 U1（50 针），H1 的 BS0 接 GND，使用带 DC 的四线 SPI。
排线方向和供电请按原板说明确认。默认竖屏，无旋转。

| 外设 | 配置 |
| --- | --- |
| 墨水屏 | BUSY 7、RST 8、DC 9、CS 10、MOSI 11、SCK 12；电源 44，低有效 |
| 共用 I2C | SDA 0、SCL 1；100 kHz |
| ES8389 | I2C 0x10；MCLK 36、BCLK 16、WS 17、DOUT 18、DIN 37 |
| NS4150B | 功放使能 19，高有效；16 kHz、16 位、双声道 |
| 按键 | BOOT 61；子板 KEY1/2/3 为 13/14/15；电源键 6 |
| 震动 / 子板 LED | 42 / 3，高有效 |
| BQ27220 / RTC / IMU | 0x55 / 0x51 / 0x18 或 0x19 |
| USB 串口 | Type-C，GPIO33/34 |

完整引脚和原板电气注意事项在 `board_pins.h`。GPIO36 同时为 Flash 电压 strap，
必须保留原板上电电平。摄像头和 TF 卡电源在本方案中保持关闭。

## 编译

需要支持 `esp32s31` 的 **ESP-IDF 6.1**，5.5 不支持该芯片。
在已激活的 6.1 环境中，从 `firmware` 目录运行：

```powershell
python tools/build_firmware.py paper-s31-offline --jobs 2
```

复用 `firmware/build`，生成 `agent_link.bin`、`merged.bin` 和对应 ELF/MAP。
编译不执行烧录。整包烧录会清除设备设置；本任务未执行烧录。

## 使用与实机验收

启动时串口输出板型和 I2C 器件状态，屏幕显示六色色块与英文操作说明。
当前字符渲染仅支持 ASCII，没有中文字库。彩色屏只能全刷，可能耗时约 20 秒；
刷新结束后进入屏幕深睡眠，不持续刷屏。

短按 BOOT 依次轮换：

1. 喇叭播放 1 kHz 音调，持续 1 秒。
2. 麦克风录音 3 秒，随后选择能量较大的声道，在左右声道回放。
3. 震动和子板 LED 联动三次。
4. 读取电池状态、RTC 时间有效标志及 IMU 标识，再刷新六色页面。

子板按键和电源键的按下/松开输出到串口。音频与屏幕操作期间暂停按键轮询，
操作结束后再按；长按电源键约 3 秒由硬件关机。
缺少电池、RTC 或 IMU 时报告缺失，不伪造读数。电池电量、电压、电流在屏幕和串口显示。
音频分配失败后需要重启再试，避免重复占用 I2S 通道。

实机需确认六色色块、文字方向、录放音、按键和震动；编译通过不能代替这些验证。
摄像头、触摸、TF 卡读写、RTC 校时和 IMU 加速度采样尚未接入本方案。
