# 第一次使用 Agent Link

[English](getting-started.md) · [环境安装](environment.zh-CN.md) · [按设备查操作](devices.zh-CN.md)

## 1. 先选你的目标

| 目标 | 下一步 |
| --- | --- |
| 让手上的设备先用起来 | 找到准确型号，再使用固件中心或让本地 AI 助手烧录 |
| 自己编译、修改固件 | 先完成[环境安装与检查](environment.zh-CN.md)，再构建指定方案 |
| 添加新硬件 | 准备原理图、板型版本和引脚，阅读[接入指南](../firmware/boards/README.md) |
| 已有设备出问题 | 记录板型、固件方案、操作步骤和错误现象，让助手按诊断流程分析 |

准备电脑、设备和**能传数据的 USB 线**。某些充电线只能供电。
确认外壳/电路板上的完整型号和版本，尤其是微雪 1.75C、WOWNNY 新旧版、Korvo 的屏幕变体。
只有“ESP32-S3”或“微雪”不足以选择固件；可以把型号、购买链接或照片提供给助手。
ESP32-P4 当前不可烧录本仓库固件，自接线示例也需要先核对引脚。

## 2. 选择连接方式

| 方式 | 使用前提 | 适合什么情况 |
| --- | --- | --- |
| WiFi | 本设备有对应 WiFi 方案、2.4 GHz 网络和平台账号 | 设备独立联网；不需要 Rorolee 手机 App |
| BLE | 安装 **Rorolee 手机 App**，并且本设备支持 | 手机负责平台连接；下载方式见下方 |
| Muse | 已有 Muse App，可访问其服务 | 独立的配对和云服务，不走 Agent Link 六位码流程 |
| 本地应用 | 对应方案提供本地功能 | 例如 OJBadge 交友，不提供云端语音和激活 |

**iOS：Rorolee 已在海外 App Store 上架，搜索 `rorolee` 即可下载。**
**安卓：到 [rorolee.com](https://rorolee.com) 下载 APK，按手机提示完成安装。**
安装后登录，并在提示时允许蓝牙/附近设备权限，再在 App 内添加设备。
若无法安装 App，或希望设备独立联网，再检查准确板型是否有 WiFi 方案。
工牌、摄像头、语音和交友是不同用途，不能认为所有固件都能聊天。

即使本地没有仓库或编译环境，也可以让 AI 助手引导网页烧录：

> 我的设备是【完整型号和版本】，想【用途】。请引导我到 https://bot.deotaland.cn/#/firmware
> 登录，筛选对应已发布固件，直接网页烧录并完成后续设置。本地没有源码，不需要先安装编译环境。

已有本地仓库、需要助手进一步识别或构建时，可说：

> 我有【完整型号和版本】，想【独立 WiFi 对话／用已有 App 连接／显示工牌】。
> 按这个仓库的 AGENTS.md 帮我确认方案。先检查 App 和环境前提，优先使用匹配的现成固件。
> 如果需要构建，按国内安装指南准备环境；确认设备和端口后烧录，最后引导我完成首次使用。

## 3. 安装固件

**网页直接烧录已发布固件，不需要本地源码仓库、Python、ESP-IDF 或编译。**在电脑 Chrome / Edge 打开
[固件中心](https://bot.deotaland.cn/#/firmware)。未登录时先完成统一认证登录。
用“硬件产品”和“芯片型号”筛选，按完整型号和用途选择相符固件，查看更新日志、版本、
硬件适用范围和设置影响，选择对应“完整烧录包”，点击该行“烧录”并按浏览器提示选择串口。
也可以点“下载固件”保留文件，但网页烧录不需要先下载到本地。
没有对应包时再考虑源码构建，不能拿相似板子的包试刷；GitHub 暂时不可访问不影响已发布固件的网页烧录。

适用范围仅限**已经支持且中心有匹配发布包的产品**。网页只写入现成固件，不修改源码、不在线编译，
也不会让未适配的板子自动获得支持。推荐 **Windows/macOS 的最新版桌面 Chrome 或 Edge**，
并要求 Web Serial 串口能力和授权；不能仅凭“Chrome 内核”判断。Safari、Firefox、手机/平板和
App 内置浏览器不在本指南支持流程内；Linux/ChromeOS 尚未完成本项目网页烧录验收。
不需要 SDK 不代表免驱动，设备仍须被系统识别为串口。

选择本设备的串口；多个端口无法分辨时，可对比插拔前后的端口列表。
没端口先检查数据线、供电、正确 USB 接口和驱动。关闭自己正在使用该端口的网页或监视器，
不要让助手关闭其他任务的程序。进入下载模式的方法随板型不同，使用目录提供的方法。
浏览器没有串口功能时使用桌面 Chrome/Edge，或按本地助手流程处理。

默认不选整片擦除。完整合并包即使不整片擦除，也可能覆盖 WiFi、配对和设备身份；
烧录前应看到清楚的影响说明。自己构建时优先分段 `idf.py flash`。
应用镜像用于 OTA，不能把它当作从 0 地址写入的整包；不要自行猜偏移。

烧录完成后看设备是否正常启动。**写入完成、启动正常、平台可用是三项独立结果。**
助手应检查实际型号和连接方式，保留本次固件对应的调试文件。

## 4. WiFi：配网后还要激活与绑定

1. 首次启动没有已存 WiFi 时，设备显示热点名称。按[设备表](devices.zh-CN.md)连接它。
   手机提示“无互联网”时选择保持连接；没有自动弹页就手动访问 `http://192.168.4.1`，注意是 **http**。
2. 输入可上网的 **2.4 GHz** WiFi 名称和密码。密码错误时重新选择/输入，不需要重新烧录。
   扫描列表没有网络可手动输入。配网网页是本地页面，连接设备热点期间不能正常上网是常见情况。
3. 页面提示成功后，让手机恢复家庭 WiFi或移动网络。查看设备显示的六位激活码；
   墨水屏应等待它完成刷新。**已经激活的设备可能直接进入在线状态，不会再显示新码。**
4. 打开[平台](https://bot.deotaland.cn)，登录自己的账号，在设备激活/添加设备入口输入设备当前六位码。
   过期时用设备新显示的码。平台菜单文字可能更新，以“激活设备／添加设备”的实际入口为准。
5. 在平台给该设备绑定 Agent；语音功能需要支持实时语音的 Agent。
   没有可选 Agent 时先在平台准备或取得可用 Agent；权限/账号问题按平台支持渠道处理，不要反复刷固件。
6. 等待设备在线，按[本设备操作](devices.zh-CN.md)选择或创建会话并开始对话。
   验收时说一句简单的话，确认得到回复，再结束通话。无屏设备由助手读取已授权的短日志确认状态。

`Set up WiFi` 是需要配网，`Activation code` 是等待激活，`No agent` 是需要平台绑定，
`Online` 是已连平台，`Voice ready` 是通话已准备好。部分设备仍显示这些英文提示。
恢复出厂或“重置激活”不能代替平台解除旧绑定。

## 5. BLE 与 Muse

BLE：在 Rorolee App 内搜索[设备表](devices.zh-CN.md)的广播名并配对，
允许该 App 所需的蓝牙/附近设备权限。优先从 App 内添加设备，不以系统蓝牙页面“连上”为成功。
需要加密配对；换手机先按本板型操作在设备端重置配对，再用新手机添加。
语音款按住说话、松开发送或按方案指定动作操作；工牌只验收显示字段。

Muse：先在 Muse App 开启开发者模式，添加 `MuseGadget-XXXXXX`，按设备 BOOT 确认，
由 App 配网。按住 BOOT 录音、松开发送。无 MiniMax 配置时可能只有文字回复；
其服务的网络可达性与 Agent Link 平台是两件事，电脑代理不会自动让设备走代理。
详见[Muse 说明](../firmware/components/muse_gadget/README.md)。

## 6. 常见恢复操作

| 现象 | 应做什么 |
| --- | --- |
| 已换路由器、旧 WiFi 失效 | 设备自动重连失败约 20 秒后会开放设置；也可用本板型提供的重新配网入口。只改 WiFi，无需重置激活 |
| 输入错误密码 | 保持设备热点连接，页面返回后重输；检查是否选择了 2.4 GHz 网络 |
| 配网页一直转圈 | 检查手机是否自动离开设备热点；网页可能随热点关闭而断开，查看设备当前提示，再恢复手机互联网 |
| WiFi 连上但平台离线 | 检查网络能否上网、设备时间/平台错误、激活和绑定；不要擅自更改编译的平台地址 |
| Already bound | 在原平台账号解除绑定，或联系该设备原持有人；重刷不会清除平台归属 |
| No agent / 无法对话 | 在平台绑定可用 Agent，确认其语音能力，再检查设备会话选择 |
| 换手机 BLE 连不上 | 先确认 App 版本和权限，再按准确板型执行本地配对重置，避免误清其他设置 |
| 屏幕黑、花屏、重启 | 停止反复刷写，记录准确型号和启动错误，由助手先分析硬件变体和日志 |

提交问题请提供：准确板型/版本、方案名、发生在哪一步、错误提示和已脱敏的短日志。
不要发送 WiFi 密码、令牌或设备认证密钥。
