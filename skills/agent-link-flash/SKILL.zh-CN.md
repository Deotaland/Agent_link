# 给 Agent Link 设备烧录固件

> 技能名 `agent-link-flash`。工具读取的是 [SKILL.md](SKILL.md) 里的英文 `name` / `description`，本文件是中文说明，内容与之一致。

规则和所有细节（烧录地址、设置步骤、常见问题）都在 `AGENTS.md`：在用户的仓库里读，或者读 <https://github.com/Deotaland/Agent_link/blob/main/AGENTS.zh-CN.md>。本技能只规定做事的顺序。

## 1. 认板子

在本技能目录下运行 `python scripts/find_board.py "<用户说的话>"`。用户给了什么就传什么：型号、产品名、厂家、店铺或链接、蓝牙名称、长什么样。

- 一块硬件对应几种固件：先问用户想让设备做什么，再选对应的固件。
- 没匹配上或匹配很弱：让用户补充信息（板子上印的字、照片、订单页）。认不出来的板子不要烧。
- `not-adapted`（未适配）：停下，告诉用户这块板子还不支持。
- `example`（接线示例）：只适用于用户自己接线的情况，先按该板子的 `config.h` 核对接线。

## 2. 拿到固件

1. **网页烧录**（AGENTS.md 路径 A）：你指导用户在固件中心操作。不能执行命令时用这条。固件中心要用户登录，你自己下载不了。
2. **手上已有的固件**加 esptool（路径 B）。
3. **自己编译**（路径 C）：用 `agent-link-build` 技能。

## 3. 征得同意

- 只读方式找串口：`python -m serial.tools.list_ports -v`。有好几个就问用户是哪个；一个都没有，就请用户用数据线插好，插档案里 `flash_port` 写的那个口（Korvo 用左边的 USB-C）。
- 写入前告诉用户：用哪个串口、哪个固件、写到哪个地址，以及数据会怎样：
  - `idf.py flash`，或者把编译产物的四个文件写到各自地址：设置和配对都保留。
  - 合并包写到 `0x0`，或者擦除：WiFi、配对、设备 ID 都会清空，之后要重新配网，并在平台上重新绑定。
- 设备插着不等于用户同意。全片擦除要用户单独同意。

## 4. 烧录

命令见 AGENTS.md 路径 B 或 C。失败时检查：下载模式（按住 BOOT 重新插）、数据线、串口被别的程序占用，或者改用 115200 波特率。改了东西再重试。用户不同意，不要为了"修复"失败的烧录去擦整片 Flash。

## 5. 检查并设置

- 看开机日志（115200 波特率，或 `idf.py -p PORT monitor`；打开串口可能会让设备重启）。`model = …` 必须和档案里的 `fw_model` 一致。还是旧固件在跑，见 AGENTS.md 常见问题"烧完还是旧固件"。
- 按板子的连接方式带用户完成设置（AGENTS.md"烧录之后"）：BLE 用 Deotaland App；WiFi 连热点，再到控制台输入 6 位码；Muse 用 Muse App 并按一下 BOOT。

## 6. 汇报

分开写这几项：
- **已烧录**：串口、固件、地址。
- **已看开机日志**：日志里报的板子、型号、连接方式。
- **设置情况**：已上线，或者用户停在哪一步。
- **未验证**：只有用户能确认的事（屏幕、声音、配对）。
